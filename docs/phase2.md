# Фаза 2: inline ghost-text подсказки

Это план, реализации пока нет.

## Цель

Пока пользователь набирает промт в поле ввода AI-чата, PromptPolish подсказывает продолжение серым текстом прямо после каретки, как автодополнение в IDE. **Tab** принимает подсказку, **Esc** или продолжение набора её убирает. Подсказка учитывает чат так же, как в MVP: для Claude предлагает структуру с тегами, для Perplexity — уточнения поиска.

Сценарий MVP по ⌥⌘P остаётся как есть: ghost-text дополняет его, а не заменяет.

## Пользовательский сценарий

1. Пользователь печатает в поле ввода claude.ai: «напиши пост про кофемолки для».
2. После паузы около 600 мс за кареткой появляется серый текст: « телеграм-канала любителей кофе, 1500 знаков, дружелюбный тон».
3. **Tab** вставляет подсказку, **Esc** скрывает её, любой другой ввод тоже скрывает и запускает новую подсказку после следующей паузы.
4. Подсказки работают только в распознанных AI-чатах и включаются в настройках (по умолчанию выключены).

## Архитектура

| Компонент | Что делает | Опора в MVP |
|---|---|---|
| `TypingObserver` | `AXObserver` на сфокусированном поле: `kAXValueChangedNotification`, `kAXSelectedTextChangedNotification`, `kAXFocusedUIElementChangedNotification`; debounce 500–700 мс | `AccessibilityText` (чтение значения, `AXWebArea`, URL) |
| `CompletionEngine` | короткое продолжение (≤ 40 токенов) по тексту до каретки; отмена при любом новом вводе | `LLMEngine` (actor, стриминг, отмена) |
| `GhostOverlay` | прозрачное окно без фокуса (`NSPanel`, `ignoresMouseEvents`) поверх поля: серый текст, начинающийся у каретки | `PanelPlacement`, `AccessibilityText.anchor` (`kAXBoundsForRangeParameterizedAttribute`) |
| `KeyInterceptor` | `CGEventTap` перехватывает Tab и Esc только пока подсказка видна, остальные клавиши пропускает | — (новое разрешение, см. ниже) |
| `Acceptor` | вставка подсказки: в нативных полях — через AX, в вебе и Electron — синтетическим набором текста (`CGEvent` с `keyboardSetUnicodeString`), без буфера обмена | `SystemTextBridge`, `KeySender` |
| `ChatTarget` + инструкции | короткая системная инструкция «допиши промт» под каждый чат | `ChatTarget`, `SystemPrompts/` |

### Модель

- Нужна задержка до первой подсказки меньше 1 секунды. Qwen3.5-4B на M2 даёт первый токен за 1–2 с на длинном контексте, этого мало. Кандидаты: **Qwen3.5-0.8B** или **Qwen3.5-2B** (MLX 4-bit), только для подсказок; основная модель остаётся для ⌥⌘P.
- Две модели одновременно на 8 ГБ — это около 4,5 ГБ. Варианты: держать маленькую модель только при включённых подсказках или выгружать большую через N минут простоя.
- Повторно использовать KV-кэш префикса: системная инструкция и уже набранный текст почти не меняются между нажатиями. В mlx-swift-lm есть prompt cache — проверить, как он работает с `ModelContainer`.
- Ограничения генерации: `maxTokens` 30–40, остановка на переводе строки или конце предложения, низкая температура.

### Разрешения

Для `CGEventTap`, который перехватывает и подавляет Tab, нужно разрешение **Input Monitoring** в дополнение к Accessibility. Его надо запросить отдельно, с объяснением, и только когда пользователь включает подсказки.

## Сложные места

- **Положение каретки в вебе и Electron.** `kAXBoundsForRange` в Chrome и Electron возвращает неточные или нулевые прямоугольники, в Safari обычно точные. Запасной вариант — показывать подсказку не inline, а маленьким «облачком» под полем.
- **IME и составной ввод.** Во время набора через IME (японский, китайский, иногда автозамена) подсказку показывать нельзя: нужно отслеживать marked text (`kAXSelectedTextRange` + `AXMarkedTextRange`, где он доступен).
- **Конфликт с собственным автодополнением сайта.** Некоторые чаты сами подсказывают или используют Tab. Нужен список исключений и отключение подсказок по сайту.
- **Нагрузка и батарея.** Генерация на каждую паузу в наборе — постоянная нагрузка на GPU. Нужны лимит частоты, отключение от батареи по настройке и отмена при смене окна.
- **Приватность.** Набранный текст обрабатывается только локально, не логируется и не сохраняется. То же правило, что в MVP.
- **Вставка без буфера обмена.** Синтетический набор Unicode-строки не трогает буфер, но медленно работает на длинных подсказках, и на него могут реагировать хоткеи сайта. Подсказки короткие, так что это приемлемо.

## Этапы

1. **Наблюдение за вводом.** `TypingObserver` + debounce, лог «пауза в наборе» в распознанных чатах. Проверка: Safari, Chrome, десктопный Claude.
2. **Оверлей без модели.** Серый статический текст у каретки, проверка позиционирования на разных сайтах и масштабах.
3. **Перехват клавиш.** `CGEventTap`, запрос Input Monitoring, Tab/Esc только при видимой подсказке.
4. **Модель для подсказок.** Маленькая модель, короткие инструкции под чаты, отмена и KV-кэш; замер задержки до первого токена.
5. **Принятие подсказки.** AX в нативных полях, Unicode-набор в вебе и Electron.
6. **Настройки.** Вкл/выкл, задержка, исключения по сайтам, работа от батареи.

## Другие идеи для фазы 2

- **Второй движок через локальный сервер** LM Studio или Ollama (OpenAI-совместимый API на `localhost`): одна копия модели на диске и в памяти, если пользователь уже держит её там.
- **Выгрузка модели после простоя**, чтобы освобождать около 3,4 ГБ памяти, и быстрая повторная загрузка (2–4 с).
- **Смягчение правила уточняющих вопросов** (например, переключатель «спрашивать только при совсем размытой идее»).
- **Автозапуск при входе** (`SMAppService`) и нотаризованная сборка для установки без Xcode.
